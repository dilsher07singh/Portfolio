2026-08-12 — SEC-001 (priority 1, security): GitHub token removed from bundle
--------------------------------------------------------------------------

WHAT WAS DONE
Picked SEC-001 as highest priority: a GitHub PAT was being inlined into the
client bundle by Vite (VITE_ prefix) and sent as an Authorization header from
the browser, so every visitor could read it. Confirmed the leak was real before
starting — the token literal was present in dist/assets/index-CchD9gBS.js.

Changes:
- .env: renamed VITE_GITHUB_KEY -> GITHUB_TOKEN (no VITE_ prefix, so Vite can
  never inline it). .env remains gitignored (.gitignore:14).
- .env.example: new, documents GITHUB_TOKEN and the read:user scope.
- scripts/fetch-github.mjs: new. Reads process.env.GITHUB_TOKEN, POSTs the same
  contributionsCollection GraphQL query, writes public/github-contributions.json.
- package.json: build is now
    node --env-file-if-exists=.env scripts/fetch-github.mjs && vite build
  Deliberately NOT an npm "prebuild" lifecycle hook — this repo is on Yarn 1.22
  today, but Yarn Berry drops pre/post script support, and RENDER-002 already
  specifies this exact inlined form. --env-file-if-exists loads .env locally;
  on Vercel the value comes from process.env directly.
- package.json / yarn.lock: axios removed (it existed for this one request).
  Side benefit: main JS chunk went 335KB -> 299KB (gzip 112KB -> 100KB).
- src/components/GithubContributions.jsx: now fetch("/github-contributions.json").
  The loading|ready|error state machine and the `cancelled` cleanup flag are
  preserved exactly as they were.
- public/github-contributions.json: generated and COMMITTED on purpose (see below).

DESIGN NOTES FOR WHOEVER IS NEXT
- fetch-github.mjs never fails the build. Missing token, non-200, or a bad
  payload all log a warning and exit 0, leaving the committed JSON in place. A
  GitHub outage should not be able to break a deploy. If you'd rather have hard
  failures, that's the `skip()` helper at the top of the file.
- The GitHub username is still hardcoded in two places: scripts/fetch-github.mjs
  (USERNAME const) and the error-state link in GithubContributions.jsx.
  POLISH-002 explicitly owns centralizing this into src/constants/index.js —
  I left it alone rather than half-doing that item.
- The day colors in the JSON are GitHub's light-theme palette (#ebedf0 for an
  empty day), which is what the old runtime query returned too. Unchanged
  behavior, but worth knowing if the heatmap ever looks washed out on the dark
  background.
- GithubContributions still renders its loading state when JS hasn't run, and
  the fetch lives in useEffect, so it should not obstruct RENDER-002's SSR pass.
